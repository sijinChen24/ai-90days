# projects/ — 五个递进项目

这里放的是能独立运行的 Python 工程，不是 notebook。
五个项目按依赖关系递进设计：后一个都用得上前一个的能力。

## 五个项目

| 目录 | 项目 | 核心技术点 |
|---|---|---|
| `01-cli-chat/` | 命令行多轮问答助手 | API 调用、流式输出、配置管理、日志 |
| `02-rag-pdf/` | PDF 知识库问答 | 文档切分、Embedding、向量库、Rerank、评测集 |
| `03-agent-tools/` | 能调工具的 Agent | ReAct 循环、工具编排、上下文压缩 |
| `04-qa-system/` | 企业知识库 或 AI 质检 | 完整工程链路：需求 → 架构 → 开发 → 评测 → 部署 |
| `05-capstone/` | 毕业项目（自选） | 多模态 或 微调 + 完整评测 + 部署 |

## 每个项目至少要有的东西

```
项目目录/
├── README.md            # 背景、方案、怎么跑起来
├── requirements.txt     # 依赖
├── src/ 或 包名/         # 源码，不是一个巨大的 main.py
└── docs/eval.md         # 评测方法与实测数字
```

最后那项 `eval.md` 最容易被省掉，但**面试时最值钱** —— 它证明你不是「跑通了」，而是「知道它多好、差在哪」。
